# 前端回归修复记录

2026-11-07，对照本地清理前的组件样式与当前工程检查。前一次“测试通过”主要覆盖规则和事件逻辑，没有覆盖真实DOM的CSS可见性，不能当作页面验收完成。

## 确认的问题与修改

1. 快捷输入条：删除旧独立发送按钮样式时，误删了一个同时包含输入框选择器的显示规则。小球能变宽，但input仍是opacity:0与visibility:hidden。恢复展开态可见性，箭头/Enter统一提交，保留中文输入法与拖动释放保护。
2. 平台流式对话：滚动效果只依赖消息数量，流式正文变长不会触发跟随。改为随消息内容更新，仅滚动聊天容器；用户上翻历史时暂停跟随，新发消息再回到底部。
3. 询价助手：scrollIntoView可能把外层工作台一起滚动。统一使用容器内部滚动，隐藏的聊天不参与滚动。
4. 平台输入框补充composition/keyCode229/repeat判断，避免中文选词确认被当成发送。
5. 为hidden面板增加强制隐藏规则，防止flex/grid显示规则覆盖。原生设置与预览弹窗增加背景滚动锁定声明和滚动边界声明；这部分仍需真实浏览器验证滚动手感。

## 已执行的验证

- 新增Happy DOM环境，实际挂载React组件并加载两份组件CSS，验证折叠/展开输入框可见性、输入与箭头/回车发送。
- 实际挂载平台对话，验证输入法不发送、Enter产生请求、流式回复渲染加粗并写入历史记录。模型响应使用确定性测试流。
- 设置页验证平台/业务分类、切换只显示一个内容区、输入在分类切换后保留、业务保存无需模型密钥、390px分类布局声明。
- 验证隐藏面板、表格滚动容器和末列定位声明，弹窗打开属性及背景锁定选择器存在。
- 验证聊天跟随正文、阅读历史不被拉回、隐藏聊天不移动工作台。
- 17组离线验证及项目子路径生产测试通过。

Happy DOM不提供真实像素布局，测试对紧凑@media语法只做等价空白规范化；动态:has背景锁定仅核对原生dialog打开状态和CSS声明，不宣称完成真实浏览器滚动验收。
