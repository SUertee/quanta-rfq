# RFQ 六阶段完善计划

制定于 2026-11-08。对象为 Quanta 航空 RFQ 工作台、右侧报价助手和 AI 对话。Goal 已启动，本文定义实施顺序与完成条件，验收结果另记。

## 当前核查

已有材料、文件正文、标准物料行、资源证据与报价快照的持久化结构。六阶段已有入口，20 组离线检查通过，真实模型曾按读取、查成本、生成草稿三工具顺序返回合成报价。真实扫描件和多附件完整业务验收仍待完成。

已复现的需求提取缺陷为带标签文字命中件号后，仅取件号、数量、单位、件状，遗漏同段描述、证书与交期，且未报告缺口。供应商资料已能分类保存，尚未完整形成可复用资源。工作台与 Agent 的匹配、检查和定价存在两套实现。聊天及中间审核状态主要在浏览器。

## 一、界面与交互修复

- 解析失败按实际原因显示“材料读取失败”或“待核对原文”，删除“可转手工单”。
- 异常巡检使用统一高度的筛选入口，菜单勾选异常类型，可多选、清空，显示筛选结果数量。菜单支持外部点击、Escape 和键盘焦点，避免横向溢出。
- 六阶段使用一致的标题、内容边界、内边距、表格行高和工具栏。件号保持完整，金额右对齐，文本与列表起点一致，减少嵌套卡片。
- 导出条件使用“已核对 0 行，尚有 1 行”“已定价 0 行，尚有 1 行”等明确数量，黄色状态直接指出阻断原因并提供定位操作。
- 删除物料表和检查条件内的“问助手”按钮及空操作列。助手侧边消息定位点仅在完整 AI 对话页面按实际需要使用，停靠助手删除。
- 处理记录代表修改与审核操作，历史快照代表曾确认的报价版本。合并为“记录”入口，以明确页签展示，空状态不占常驻区块。

## 二、上下文引用与对话执行

- 物料行、原文与依据可拖入右侧助手，引用携带询价 ID、行 ID、内容 ID、来源位置及当前版本。
- 引用在输入区作为可移除条目展示，发送后随消息保留。支持文字选择拖放，触屏和键盘提供等价的引用操作。
- 用户指令与引用材料分离，服务端按标识重新读取业务事实，引用中的文字作为数据处理。
- 右侧助手与完整 AI 对话共享上传、引用和执行能力。上传内容后创建询价并返回任务与阶段结果卡，继续核对同一任务。
- 普通问答、检查、生成草稿和确认导出分别路由。执行过程显示用户能理解的工具进度与结果摘要。

## 三、接收与完整需求提取

- 保持 source、file_type、document_type 语义稳定，原件、正文、标准行分层保存。
- 完整抽取描述、数量、单位、件状、证书、需求日期与报价截止日期；规则已命中的文字仍需检查剩余要求。
- 多文件保留上传关联及邮件父子关系。多个来源疑似同一物料先展示冲突，避免静默合并。
- 对模型结果做来源验证、字段级归一化与遗漏检测。缺项、OCR 失败、提取失败可定位和重试。
- 使用真实样本验证 EML 与附件、Excel、文本 PDF、扫描 PDF、图片和粘贴文字。

## 四、统一依据、检查与定价

- 供应商报价与库存资料提取成标准资源，人工确认后入库，保存来源、价格币种、单位、件状、MOQ、证书、交期、生效日期和有效期。
- 工作台、巡检和 Agent 共用匹配、条件检查与定价服务。候选与已选依据分离，采用具体资源和版本生成草稿。
- 严格件号及明确授权的替代关系区分展示。未满足单位、件状、数量、币种、证书或交期的候选保留冲突原因。
- 统一日期、加价率与毛利率、汇率、折扣和运费口径。无依据行保持空价格。
- 物料、依据或策略改变后撤销旧审核，防止旧结果直接导出。

## 五、审核、签名与导出

- 保存审核和定价的服务端版本，支持刷新恢复与并发版本检查，聊天关联到同一询价。
- 手写签名支持鼠标和触屏，提供清除、重签和预览，导出时嵌入客户报价单并保存签名快照。此功能是签名图像采集，实施范围为报价确认记录。
- 用户确认后生成客户报价单及内部依据文件，客户版不包含成本与内部备注。
- 记录 Agent 定义和提示版本、工具执行、依据快照、人工操作、签名与导出版本。失败与未完成流程显示对应状态。

## 六、验收与发布

验收分别从工作台创建询价、右侧助手引用提问、AI 对话上传创建询价三个入口执行。同一份材料应产生一致物料、候选、检查和报价。

必须覆盖正常报价、缺数量、单位冲突、MOQ 不足、过期报价、缺证书、交期冲突、无价格依据、模型失败、OCR 失败、刷新中断、修改后审核失效。每例检查数据库记录和最终导出内容。

UI 验收覆盖桌面、右侧停靠和窄屏。检查页面边缘、列表行高、筛选菜单、滚动范围、拖放引用、消息流、签名操作及导出阻断提示。保留截图及样本来源，区分合成与真实材料。

完成后运行构建、回归、子路径生产验证和密钥扫描，部署到 projects.suertexu.com/quanta-rfq，并验证线上静态资源、接口与实际操作。Goal 仅在上述要求完成且无必需剩余项时标记完成。

## 2026-11-08 引用交互实施核查

已接入物料、原文、资源依据的拖动引用，提供“引用”按钮作为键盘和触屏入口。输入区显示可移除的引用条目，发送后随消息保存，引用草稿在页面重建后恢复，失败时可重试，后续追问继续引用同一来源。

服务端对询价、物料、原文及证据标识重新查询，校验物料版本与取数时间，拒绝过期或跨询价引用。客户端显示摘录不作为价格事实，引用上下文保留服务端字段白名单。普通选中文字按用户提供的材料处理。

实测使用已有合成材料“件号 an3-5a、数量 10、Each、fn”。浏览器原生拖动进入右侧停靠助手后显示引用卡，真实模型解释了 Each 和 FN，返回流式回复。HTTP 无效询价引用返回 409。21 组离线检查、类型构建及生产子路径验证通过，包含引用移除、恢复、无文字发送、追问承接、失败保留和来源校验回归。截图保存在工程本地验收目录，完整六阶段验收仍待后续完成。

## 2026-11-08 共享规则实施核查

归一化、完整件号匹配、候选条件检查和建议价计算已集中到 `app/shared/`，工作台、异常巡检与 Agent 使用同一实现。保留完整后缀，单位别名统一，币种使用配置汇率。候选逐条检查库存或 MOQ、件状、证书、日期、交期、价格，以及供应商税基与来源授权。缺项保留原因。单一合规库存优先，其次取合规供应商最低折算成本；多条库存记录需人工选择，该策略是本轮实现选择，后续人工选源交互仍待完善。

报价卡、预览与内部成本导出采用已选依据。MOQ 冲突保留客户原始数量，避免自动提高需求量。毛利底线改为成本除以一减毛利率，目标售价继续使用成本加价率。规则版本为 2，Agent 定义版本为 1.3.0，原服务端归一化与资源检查模块保留兼容入口。

22 组离线验证、类型构建、生产子路径验证通过。真实模型合成供应商案例完成三个工具，条件齐全时建议单价 112.50，缺单位时空价。浏览器既有合成 AN3-5A 案例中，工作台与助手均为 17.96，依据页标出内部库存已选依据。截图为 `.deployment/shared-rules.jpg`。真实供应商资料入库、完整多附件提取、服务端审核及策略版本、签名与三个入口的全链路验收仍有缺口。本轮 Claude 调用因账号五小时用量限制未完成独立复核。


## 2026-11-08 签名与导出实施核查

第六阶段新增手写签名入口，沿用现有对话框、输入和按钮样式，支持鼠标及触屏笔画、清除、重签与预览。签名为有界点集，保存签署人、时间与报价内容哈希，不接收原始 HTML 或 SVG。报价内容包括策略、公司、需求、选中依据、价格和核对结果，变化后旧签名立即失效。签名为可选确认记录，现有人工核对及导出闸门继续生效。签名草稿在本机按询价恢复，已导出签名与内容存入服务端报价快照；跨设备审核及草稿同步尚待实施。

客户 HTML 嵌入受控生成的签名图，签署人按文本转义，保留打印与另存 PDF。服务端在保存快照前验证签名绑定、数量、价格合计及当前已选依据，导出请求期间内容变化则取消本次下载。运费计算已复用共享规则。

23 组离线检查通过，覆盖鼠标/触屏、笔画取消、清除与重签、恢复/失效、格式/范围校验、合计/过期依据拒绝及客户 HTML 转义。浏览器在既有合成询价书写 QA 测试签名，导出客户文件合计 179.60，服务端保存快照 4，内部成本未出现在客户文件。改单价到 18.00 后签名与导出状态清除。实测 388×845 CSS 视口中签名对话框位于左右各 16px 内，无页面横向溢出。截图为 `.deployment/signature-export.jpg` 与 `.deployment/signature-mobile.jpg`。这些验证不代表六阶段完整业务验收。

## 2026-11-08 服务端审核版本实施核查

正式接收链创建的询价通过 quote_draft 保存当前价格、人工核对、跳过行、补充成本和该询价采用的完整定价策略。quote_draft_revision 追加版本、操作者、时间和幂等请求标识。服务端按版本及来源指纹检查并发，来源指纹包括需求、证据快照、共享规则版本与业务日期。物料、依据或策略变化后原核对失效，来源变更还会清除旧价格。导出须引用当前已保存审核版本，服务器重新验证价格、核对、策略、依据和合计。

浏览器串行合并保存，发送前记录本机待保存内容，刷新后可重放未完成请求。同一请求重试不重复写入。冲突明确提示，可重试或载入服务端版本；载入服务端版本会舍弃本机未保存内容。冲突重试保留原基准版本，避免覆盖另一窗口的价格。保存中、失败或冲突时阻止核对及导出。

已有正式询价首次接入时迁移本机价格、补充成本和跳过行，旧本机核对标记清除后重新确认。打开询价时恢复其已保存策略是本轮实现决定。旧演示 JSON 任务暂保留本机状态，签名草稿与聊天记录也仍为本机存储，完整跨设备和各入口联动仍有缺口。

24 组离线检查、生产构建与子路径验证通过。新增检查覆盖 SQLite 重载、幂等重试、持久化失败回滚、并发冲突、来源及策略变更失效、恢复与待保存记录重放。浏览器合成 AN3-5A 询价验证单价 18 与核对结果刷新恢复，客户导出合计 180；另一窗口改价到 21 后，本窗口的 22 被拒绝，反复重试仍保持服务端 21。显式载入后重新核对，导出合计 210，服务端快照 6 绑定审核版本 6。旧审核版本导出返回 409。截图为 `.deployment/draft-restore-export.jpg`。本轮未新增真实 OCR、真实多附件或完整六阶段验收结论。

## 2026-11-08 Agent 完成状态修正

未调用工具或未完成草稿工具的报价请求返回失败状态，审计保存 failed，聊天允许重新发送，避免把空结果显示成已完成。完成读取与成本查询的依据追问可以返回依据结果，明确要求生成草稿时必须完成草稿工具。原有模型原文与隐藏推理不透传。使用实际 createAgent 循环配合脚本模型验证无工具、只完成部分工具及依据追问三种情况，前端回归验证失败状态可恢复。

服务端审核版本已部署为 3bcaaad，公开工作台、静态资源、健康检查通过，新增审核表存在，无效草稿返回 400，未知询价返回 404。部署前保留数据库备份。

## 2026-11-08 对话正式接收实施核查

完整 AI 对话与右侧助手接入正式询价接收。用户上传文件后发送，或在对话中明确新建询价，可保存原件并进入相同的标准物料与依据链。空文本携带文件默认创建新询价；明确解释、翻译或操作教程的问题保留在问答流程。用户请求保留在本机接收记录中，文件通过 IndexedDB 标识读取完整原始字节，聊天节选不替代正式来源。source 为 chat，file_type 与 document_type 延用接收模块定义。

接收后返回文件数、物料数和业务缺口回执，原对话关联到新询价并可继续生成草稿，工作台展示同一份物料和依据。导出仍通过人工核对及服务端审核版本检查。没有提取到物料时保留回执与问答能力，原件可从工作台核对。

请求 ID 在发送前持久化，接收失败或停止等待后可以重试，刷新后恢复待接收记录；服务端已接收但响应丢失时沿用原请求 ID，避免重复创建。重试命中仍在处理的任务时轮询原任务结果。放弃重试只结束本机等待，已保存服务端材料仍保留在询价记录。

25 组离线检查、构建与生产子路径验证通过。新增 React 原生粘贴验收连接实际 SQLite 接收服务，验证原件字节、chat 来源、CSV 类型、标准行和库存证据；模拟响应丢失并重建组件后重试，数据库仍只有一份询价。操作教程不创建任务，本机原件丢失给出重新添加提示。
