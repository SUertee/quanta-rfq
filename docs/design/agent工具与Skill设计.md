# RFQ Agent 工具与 Skill 设计

更新：2026-11-06。依据用户确认的首版流程：上传询价后，系统自动提取需求、查询依据、检查条件，按已配置规则计算报价草稿；缺依据的行留空，最终由人审核。本文是目标设计，不代表以下工具已经注册或验收。

## 当前实现对照（2026-11-07）

当前registry版本1.1.0实际只有 read_inquiry、lookup_costs、build_quote_draft 三个工具，不是下文六工具。上传解析、依据刷新、人工核对与导出由其他业务服务及UI协同完成；已用一行合成CSV真实走通六阶段，不能据此说模型注册或自主执行了六个工具。

现行scope只允许当前询价所请求的行，字段以数据库为准；用户接受建议价后仍需人工核对。导出先等待服务端snapshot成功，不自动外发。完整当前能力以 [Agent能力设计](agent能力设计.md) 为准，同库审计见 [审计接口](Agent运行审计接口.md)，本例结果见星宫04验收报告。以下六工具与三个Skill仍为目标拆分。

## 入口与执行职责

「新建询价」上传与「对话中明确委托处理附件」进入同一服务。仅查看文件或咨询不创建业务任务；处理委托明确后，无需再让用户输入启动提示词。首版不连接邮箱，不接外部客户聊天室，不自动发送。

服务端校验附件并创建任务、分配稳定 ID、保存原件及哈希、确定业务日期与企业数据快照，然后启动自动分析。Agent 不能凭模型生成的 ID 读取其他任务或任意本地路径。仅询问来源或风险的追问，只读取相关记录，不重复创建任务或报价。

固定主流程由服务端保证：原件 → 结构化需求 → 报价依据 → 条件检查 → 定价规则 → 草稿保存。Agent 负责语义提取、决定需要哪些查询、解释异常与组织补充问题；精确匹配、校验、金额计算、版本与权限由程序执行。模型未调用必要工具、工具失败或被取消时，服务端不得把该阶段记为成功。

## 六个目标工具

| 名称 | 用途与输入 | 返回结果 | 副作用及失败行为 |
| --- | --- | --- | --- |
| read_inquiry | 读取服务端绑定的当前询价；可选版本、行 ID | 原始附件清单、已解析物料、业务日期、状态、版本、已有草稿和来源定位 | 只读；跨任务 ID 拒绝；找不到返回 not_found，不创建新记录 |
| extract_requirements | 解析本任务的 documentIds；只接受已上传附件 ID | 候选客户信息、物料行、件号、描述、数量、单位、件状、证书、交期、缺失或冲突项及原文位置 | 返回候选结构；由服务端校验并保存版本。失败附件单列，不把部分成功说成完整解析 |
| lookup_quote_evidence | 行 ID、需求版本；精确件号优先，必要条件作为筛选项 | 库存、内部成本、供应商候选报价、历史参考及各自币种、计价单位、数量条件、日期、来源 ID | 只读；无匹配返回空列表；多候选并列，不能默选最低价；历史售价不充当当前采购成本 |
| validate_quote_conditions | 需求版本、候选 evidenceIds、业务日期、适用规则版本 | 每行每条件的 pass / conflict / missing / not_applicable，原因、证据、是否阻断出价和是否阻断最终确认 | 程序校验；明确区分未要求与缺信息。不能把“证书字样存在”当作质量核验；规则不支持返回 unsupported |
| get_pricing_policy | 当前任务及适用范围；模型不能自行传入新费率 | 已确认 policyId、版本、生效范围、成本选择规则、加价/毛利口径、税运与舍入规则 | 只读；没有配置返回 missing_policy，禁止悄悄使用默认 25% 等参数 |
| build_quote_draft | 需求、依据、检查、定价策略的版本引用；mode=analysis 或 draft | 逐行采用依据、成本、公式、建议单价、金额、币种、缺口、待审核状态及汇总 | 确定性计算；拒绝过期输入或跳过门禁。analysis 不出价；不批准、不发送、不修改库存 |

read_inquiry 在创建任务后可读到待解析原件，因此能够支持上传入口。当前实现的 read_inquiry 仅读取请求里的已解析行，不能把同名目标工具视为已经具备附件读取能力。

工具统一返回：status（ok / partial / not_found / invalid_input / unsupported / error）、taskId、inputVersion、data、issues、evidenceRefs。成功空结果与工具故障分开；引用必须是服务端已存在的记录。模型提供的成本数字和来源文字不能直接成为权威依据。

## 数据与金额契约

- 原文定位保留 documentId 及邮件段落、PDF 页/位置、Excel 工作表/行/单元格等可用位置；没有精确定位时注明能力限制，不生成假页码。
- 件号原值与规范化值分开保存；不擅自删除后缀或把近似件号当精确匹配。数量、单位等冲突保留候选，不让模型择一后掩盖冲突。
- 客户需求、当前供应商报价、内部成本、历史售价是不同数据类型。有效期不存在表示未知，不能凭日期猜有效或过期。
- 单位不明、币种无法统一、无适用成本、无定价规则、关键需求冲突等相关阻断项存在时，suggestedUnitPrice 与 amount 均为 null，不用 0 代替未知。
- 有有效成本且满足出价条件，但仍需人工核验证书等事项时，可以返回标记条件未决的价格草稿；最终确认仍被阻断。客户明确要求但证书依据不足时，是否允许条件性出价由业务规则明确决定，不能由模型放行。
- 加价率公式为成本 × (1 + 加价率)；目标毛利率公式为成本 ÷ (1 − 毛利率)。工具根据 policy 明确选择，不让模型自行混用。金额使用十进制定点计算，舍入位数与时机由策略定义。
- 不跨币种直接合计。未报价行不计为零元成交；同时返回已计价金额、已计价行数、未计价行数，避免把部分小计标成完整总价。
- 需求、依据、策略变化使受影响检查和草稿失效。最终确认绑定全部版本；保存草稿不等于人工确认。

## 三个业务 Skill

这里的 Skill 指产品内可复用的流程说明、领域词典、规则与模板，不是新增模型、不等于一个工具，也不是安装给 Codex 的个人技能。MVP 可以由服务端按阶段加载可信版本，无需再增加动态发现或执行任意脚本的框架。

| Skill | 触发阶段 | 内容和调用工具 | 产出 |
| --- | --- | --- | --- |
| rfq-intake：询价整理 | 新材料导入，或用户补充要求 | 邮件正文与附件识别、字段词典、单位/件状原值保留、重复材料识别、冲突与缺失规范；read_inquiry → extract_requirements | 可核对物料表、原文引用、补充问题 |
| rfq-evidence-review：依据匹配与条件检查 | 需求提取完成，或需求/依据变化 | 件号匹配规则、库存与成本适用性、供应商报价条件、有效期/MOQ/证书/交期检查表；lookup_quote_evidence → validate_quote_conditions | 候选依据、逐行检查、出价与确认阻断项 |
| rfq-draft：规则报价与审核交接 | 有可用依据，用户允许生成草稿 | 成本采用规则、配置引用、计算与舍入、双版本导出字段清单；get_pricing_policy → build_quote_draft | 有价格与留空行并存的草稿、简短交接摘要 |

每个 Skill 至少记录 id、version、适用品类、业务来源、规则编号、所需输入、允许工具、完成条件与反例。航空件状/证书规则未经专业确认时标记待核验；政府采购法规不直接套用于航材商业询价。缺数据时汇总提问，不逐行反复打断可继续执行的工作。

## 不交给模型的操作

原件接收、创建任务、去重与重复请求幂等、写数据库、版本失效、取消运行、记录进度、权限校验由服务端处理。模型结果只能通过 schema 和业务验证后保存。后台任务队列和跨进程恢复属于工程能力，不能仅凭 prompt 声称支持。

审核确认与导出由明确的 UI 操作触发。服务端校验审核版本及阻断条件，客户版排除成本和内部毛利；导出无外发副作用。MVP 不提供 send_email、approve_quote、update_inventory、任意 SQL、任意文件读取或联网估价工具。

## 当前代码对照及迁移

2026-11-06静态核对 app/server/agent.mjs：现有工具为 read_inquiry、lookup_costs、build_quote_draft；读取已解析行，按精确件号查询内部成本，包含部分单位/件状/库存检查。当时三工具路径未覆盖原始附件解析、供应商报价检索或完整证书交期检查；2026-11-07已有同库运行审计持久化，但不等于成本完整快照或模型恢复。

buildDraft 中存在缺省加价率 0.25、加急系数 0.1 和批量折扣 0.05，以及最近采购价优先于平均成本的选择。它们是当前代码行为，不能自动当成用户已配置的有效业务规则。迁移时应外置为有版本的明确配置；无规则时保持待核价。

先复用现有工具循环和计算代码，补任务/附件/来源/版本契约，再增加解析与供应商依据，拆出独立检查和策略工具，最后联通上传自动启动、对话追问、持久记录与审核导出。此顺序是实现建议，不表示本次已完成代码迁移。

## 验收用例

1. 同一份材料从上传和对话入口进入，生成同结构任务；重复请求不重复创建。
2. 缺数量、件号后缀不一致、单位冲突，保留原值和定位，相关价格为空。
3. 多条供应商报价分别有不同MOQ、币种和有效期，不能只按数字最小选取。
4. 有成本、明确加价率和适用条件时，两种入口的工具计算结果相同。
5. 无策略、无成本或解析失败时保留缺口，摘要不得说全单已完成报价。
6. 数量或依据修改后旧草稿不可确认；取消或迟到结果不可覆盖新版本。
7. 邮件/附件含越权指令时作为原文保存，不执行外发、审批或读取密钥。
8. 保存后重启可查原件、依据和草稿；历史查询保留条件，不把旧价当当前承诺。
9. 客户版导出不包含内部成本/毛利；有未计价行时不得显示为全单完整总价。

本次仅完成设计与静态对照，以上用例未作为通过结果。
