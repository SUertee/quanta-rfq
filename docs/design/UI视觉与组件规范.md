# UI 视觉与组件规范

## 2026-11-08 流程组件修订

异常巡检使用“筛选”菜单勾选一个或多个类型，数量在入口旁展示。菜单不放入会裁切的横向滚动容器，支持外部点击及 Escape 关闭。

物料表和条件检查删除“问助手”重复入口。右侧停靠助手不显示消息定位点。工作台阶段状态使用明确的行数与待处理数量，确认导出以可点击定位的阻断清单呈现。操作记录与报价版本归入“记录”对话框，分别使用页签查看，避免在阶段正文中展开空记录。

物料、原文和报价依据可以拖入助手；键盘和触屏使用“引用”按钮。引用条目与用户指令分开，引用显示来源及节选，发送后保留在消息中。输入区引用可移除，每轮最多 6 项，来源变化时提示重新引用。

完整实施与验收范围见 [RFQ 六阶段完善计划](RFQ六阶段完善计划.md)。上述修订优先于后文同一组件的历史描述。

规范日期：2026-11-06。适用工程：`版本对比/merged-workbench`。本文件是视觉与组件尺寸的现行基准；六阶段业务职责仍见 [UI 组件与六阶段导航规范](UI组件与六阶段导航规范.md) 中未被后续设计替代的约定。数值是设计要求，不代表所有页面已经满足或通过验收。

## 设计目标

工作台围绕一份询价的反复核对操作组织，保持高信息密度、可辨认的状态与持续可见的业务上下文。六阶段帮助定位操作，不将“看过页面”表示为业务已完成。助手用于委托、追问与证据解释，表格和草稿用于确认业务事实。

视觉层级依靠字号、字重、间距与表面区分；不把所有元素做成同一种圆角胶囊，也不通过大段功能介绍占用操作区域。原文、缺失原因、来源与真实错误必须保留。

## 按用途设置圆角

| 元素 | 圆角 | 使用边界 |
| --- | --- | --- |
| 文字操作按钮（含返回） | `999px` | 行动入口；桌面默认高度 40px，触屏点击区域至少 44px，字号 14px |
| 独立图标按钮 | `10px` | 正方形点击区域，与文字按钮同高；返回箭头属于文字按钮内部，不另作图标按钮 |
| 筛选 tab、分段选项 | `10px` | 只改变当前数据视图或筛选状态，不伪装成提交按钮 |
| 输入框、下拉框、文本框 | `10px` | 与按钮明确区分，错误与焦点状态不能改变几何尺寸 |
| badge、状态标签 | `6px` | 默认不可点击，不靠颜色单独表达含义 |
| 菜单、tooltip | `12px` | 浮层避开焦点元素与视口边缘，可通过 Escape 关闭 |
| panel、内容分区 | `16px` | 主要承载表格、证据与结果，避免多层卡片嵌套 |
| modal、对话框 | `20px` | 有标题、关闭和明确动作，键盘焦点可控 |
| avatar、阶段点 | `50%` | 正圆且宽高一致；阶段点的可点击区域独立于可见小圆点 |

圆角按组件角色绑定 token。禁止用单个全局 `border-radius:999px` 覆盖输入、tab、badge、表格容器或 modal。按钮内部文本不换行，尺寸不足时优先缩短动作名称。

## 字号与密度

| 内容 | 字号 |
| --- | --- |
| 正文、主要说明与对话内容 | 15px |
| 表格、按钮和主要控件 | 14px |
| 辅助文字、来源及日期 | 13px |
| 紧凑 count 数字 | 可用 12px |

12px 仅用于独立数量，不承载错误原因、字段名称或需要阅读的业务正文。表格金额右对齐、币种与单位明确；长件号、邮件主题与来源可查看完整内容。桌面紧凑布局不能降低触屏可操作面积。

## 组件状态

按钮提供默认、悬停、焦点、按下、禁用和运行中状态；运行中保留明确停止入口。输入提供未编辑、已修改、校验失败、保存中与已保存反馈。筛选显示选中态和实际数量，筛选为空不等于无业务数据。

六阶段点必须支持键盘焦点与可访问名称；选中态表示当前阅读区域，完成态来自材料、需求缺口、证据、核对、定价及导出记录。小圆点外有足够点击区域，触屏通过主区域标题理解当前阶段。

原文、报价依据、缺口清单与待补充事项直接展示，禁止使用 details/summary 三角折叠入口。审计通过明确按钮进入记录视图，业务阻断原因始终可见。生成草稿与已确认、已导出是不同状态；旧报价因数量或策略变化失效时给出明确反馈。

## 验收方式

先验证 token 与用途映射，再检查桌面与窄屏的实际渲染、键盘焦点、表格滚动、浮层遮挡及触屏点击面积。需要检查输入、tab、badge、菜单、panel 和 modal，不能只截图一个按钮后宣称全站统一。

实际截图、构建与业务测试结论留在星宫 04 开发实施的验收报告；源码和完整日志仍在 Programming。本文件仅给要求，不提前记录“通过”。


## 浮动助手与直接操作（2026-11-07）

助手标题栏可拖动；位移超过6px后收成52px圆球，松手保留位置，点击恢复原对话。小球支持拖动和方向键移动，记住本机位置，视口缩小时约束回屏幕内。放大对话不参与拖动。标题栏内按钮与输入不触发拖动；拖动结束的释放不误触打开。

库存页只保留一个页面标题，表格工具栏保留紧凑搜索、添加物料与导入。移除自定义字段创建入口，已有字段与数据继续显示；正常数据库连接不显示常驻状态标签。构建及拖动状态逻辑测试通过；浏览器连接超时，实际鼠标/触屏视觉验收尚未完成。


## 六阶段标题与纵向步骤导航（2026-11-07）

右侧标题仅显示阶段名称，不重复“01 / 06”，询价标题下不加装饰横线。右侧按 1–6 连续展开原始材料、物料核对、报价依据、条件检查、报价草稿和确认导出，各区块有独立阶段标题，不再切换或隐藏阶段面板。左侧44px纵向步骤栏固定定位，点击节点滚动到对应区域并转移键盘焦点，点击定位期间锁定目标高亮，避免平滑滚动经过中间阶段时反复跳亮；滚动停止后恢复自动跟随，滚轮、触屏或滚动键输入可立即接管。手动滚动同步高亮当前阅读阶段；减少动态效果偏好启用时直接定位。六节点用连接线串联，当前节点深色高亮，真实完成的非当前节点显示勾选，待处理节点使用警示边框。查看或滚动不改变完成、人工审核与导出状态。阶段名称与实际状态可悬停/键盘聚焦查看，正文不增加说明段落。该约定取代单阶段面板和上一/下一步切换。构建、阶段状态、滚动导航逻辑及导出审核门槛测试通过；浏览器连接超时，实际滚动与视觉截图尚未验收。


## 流程内容优先（2026-11-07）

删除常驻的模型检测、AI 在线与模型未连接标签。模型可用性仍用于控制相关操作，实际失败保留反馈；工作区不再为在线状态单独包装卡片。需求汇总、处理记录与历史快照保留实际操作入口，人工核对、缺口、报价依据与导出阻断信息继续可见。构建、导航高亮锁定/用户接管/恢复跟随、阶段状态和导出门槛测试通过；本轮未完成浏览器视觉验收。


## 设置分类导航（2026-11-07）

设置窗口采用左侧分类、右侧内容的布局，设置窗口主标题统一为“设置”。导航使用有明确业务对象的名称：模型配置、报价策略、业务规则、单位换算、运费核算、企业资料；避免“规则”“单位”等脱离上下文的泛称。内容标题使用完整专业名称：模型服务与文档解析配置、报价定价策略、业务规则与汇率、物料单位换算、货运成本与费用分摊、企业资料与报价单信息。每次显示一个分类，分类切换不保存、不丢弃草稿；保留统一保存与未保存关闭提醒。模型和策略校验失败时跳到对应分类。单位换算继续按原接口即时保存，其行为不改写成草稿保存。

分类可通过方向键、Home/End 切换，内容关联 tabpanel；窄屏转为顶部横向分类栏，内容单独滚动，底部保存操作持续可达。禁止用三角折叠菜单代替分类导航。构建通过，尚未完成浏览器视觉验收。


## 平台设置与业务配置分离（2026-11-07）

平台“设置”只管理模型、联网搜索与文档解析服务；主导航独立提供“业务配置”，管理报价策略、业务规则、单位换算、运费核算及企业资料。两个入口的保存分别校验与提交各自数据，业务配置无需先填写模型密钥，平台设置不覆盖企业资料或报价策略。企业资料作为报价单业务信息维护，不归为平台技术设置。关闭时仍保留未保存修改提醒，移除空闲状态的“设置已保存”常驻文字。构建通过，浏览器视觉尚未验收。


## 助手快捷输入与对话记录（2026-11-07）

右下角助手有三个状态：收起为小球；鼠标悬停或键盘聚焦展开快捷输入；发送后打开小聊天室。直接点击小球同样打开。仅在位移达到6px的真实拖动发生后捕获指针，避免普通点击被父容器截走；拖动仍收球并记住位置。快捷指令由当前会话接收一次，切换询价不重复发送旧指令。

没有选中询价时提供只读平台问答，通过服务端 createAgent 与功能范围工具回答流程问题，不读取其他询价、不生成无依据价格。选中询价后使用原报价 Agent 的工具、范围校验及审核边界。平台问答不产生报价审核记录。

主导航增加“对话记录”，助手标题栏提供同一入口。现阶段复用浏览器本地存储 rfq-chat-v1，分别记录平台会话、整单会话和物料行会话；消息追加角色、正文和创建时间。历史页集中阅读，可继续平台对话或打开对应询价；尚未实现跨设备同步、同一询价的多个命名会话、历史物料行会话原位续聊。询价执行审计仍保存在后端 agent_runs/agent_events，与聊天历史用途不同。

构建、悬停快捷发送、拖动边界与报价助手交互逻辑测试通过；平台问答真实模型接口返回成功。浏览器控制超时，尚未完成视觉和实际鼠标悬停验收。


## AI 对话页面与整体变形入口（2026-11-07）

主导航“对话记录”升级为“AI 对话”。同一页面左侧选择历史会话，右侧直接使用原报价助手或平台助手输入、执行、停止和查看结果；保留对应询价的整单/物料行范围，浮窗与页面复用同一组件实例与存储。平台问答仍是一个持续会话，不伪装成多会话创建。被删除询价的历史入口暂不可继续执行。

入口必须是同一个52px深色小球外壳横向伸展成340px输入条，禁止旁边新增白色输入框。开始拖动立即回到52px圆球，拖动中和刚释放后不展开；离开后重新悬停才展开。支持键盘与减少动效偏好。构建、拖动收起、释放锁定、重新悬停及快捷发送逻辑测试通过，尚未完成浏览器视觉验收。


## 新建会话、附件与询价关联（2026-11-07）

AI对话左栏主动作是“新建对话”，创建独立本地会话标识而非重开同一平台线程。搜索匹配完整消息正文、首条消息标题及询价名称。最近/已归档视图提供归档与恢复，保留原消息和关联。对话顶部可搜索并关联既有询价或解除关联；自定义会话关联询价后原对话不丢失，报价工具仍使用当前询价真实行与审核边界。

附件支持选择、拖放及浏览器ClipboardEvent提供的图片/文件粘贴。文本、CSV、Excel、邮件和PDF复用统一文件解析器；图片与扫描PDF经OCR服务，未配置、失败、无文字均明确显示。每次最多6个附件、每个8MB、总计24MB；聊天上下文有长度上限，节选状态明确提示。原始文件不写入浏览器聊天存储，读取文本保留到消息/上下文；点击“生成询价任务”才走正式文件、内容、需求与依据的接收链并保存原件。平台问答上下文视为不可信材料，不执行附件中的指令。

普通状态仍为Q小球；悬停整体伸展后右侧变为青色↑发送按钮，拖动即回到Q。构建、会话新建/归档/恢复/关联/解除隔离、文件解析/失败/节选标记、拖动与快捷发送、原Agent及询价接收回归通过。服务端文本附件HTTP读取通过；真实OCR服务识别与浏览器视觉/剪贴板实际操作未验收。聊天消息和关联元数据目前仍仅存于本机浏览器，未做跨设备同步。


## 流式回复与 Markdown（2026-11-07）

平台对话通过服务端 createAgent.stream 的消息流与 NDJSON 响应逐段传输，前端使用 ReadableStream/TextDecoder 处理跨块中文、分行事件、结束与错误，保留部分回复并明确显示中断。停止沿用 AbortController。标准AI消息直接流式显示；当前网关以generic消息把未标记推理放在 </think> 前，必须丢弃该前缀后才显示正文，不展示推理链。平台能力直接写入系统上下文，平台问答不使用报价工具；询价Agent的三个工具及完整报价回执保持原审核边界，金额不以未完成的文本流作为可接受报价。

浮窗和AI对话页共用 react-markdown + remark-gfm，支持加粗、段落、列表、标题、代码与表格。跳过原始HTML，外部链接以安全链接规则处理，不插入模型生成的HTML。旧消息也用同一组件解析。2026-11-07 本机后端模型为 DeepSeek-V4.1-Flash，通过 token-api.yicloud.com OpenAI兼容网关调用；凭据不进入聊天或说明文档。

真实HTTP流测试返回200、14段正文，首段约764ms、总计906ms，仅为该次请求数据；另通过拆分推理标签、跨字节中文、逐段更新、连接截断、Markdown加粗/列表及原始HTML过滤测试。构建与报价助手交互回归通过；实际浏览器视觉尚未验收。


## 极简输入与本地附件预览（2026-11-07）

按用户最终要求，不留“＋”、添加附件、粘贴文件或生成询价任务按钮。输入区仅保留文本输入和发送/停止，整个助手对话区域接收原生粘贴和拖放；普通文本粘贴不受影响。图片显示缩略图，文件显示文件卡片，点击打开独立预览，草稿附件提供移除按钮。发送后预览作为消息附件保留。图片展示读取本机原图，不依赖OCR成功；识别状态仅为“读取中/待识别”等紧凑标记，具体原因进入文件预览显示。

文件Blob存于本机IndexedDB quanta-chat-files，消息在原聊天存储中仅记录文件标识、名称、类型、状态和必要摘录；预览生成Object URL并在卸载时释放。已保存消息可重新从本机恢复预览，浏览器数据清理后原文件可能不可用。图片、PDF、文本可预览，Excel等格式优先显示提取文本并允许下载原文件。不把HTML作为附件页面执行。

附件移除立即清除对应模型上下文，晚到OCR结果不能恢复已移除卡片；不同询价切换时重新建立附件组件与会话范围。报价附件上下文独立于用户输入，避免覆盖或把长段原文塞进输入框。平台对话与报价结果保持Markdown渲染。AI页面收紧标题、历史项和消息宽度，避免重复操作条。

构建、无按钮/无加号检查、原生粘贴事件、OCR前显示图片卡片、移除后晚到结果隔离、上下文清除、原Agent交互/范围及流式Markdown测试通过。浏览器实际预览、系统剪贴板和视觉布局仍未验收。

## 报价签名（2026-11-08）

第六阶段以一行展示签名状态、签名预览与“手写签名／重新签名／清除签名”。签名对话框复用现有 Modal、输入及按钮，签署人与笔画区上下排列，清除置左，取消与确认置右。笔画区支持鼠标、触屏及指针取消，触屏书写区域禁止页面滚动，关闭对话框后恢复页面操作。窄屏对话框保留两侧 16px，避免横向溢出。

签名绑定当前报价内容，变化时即时清除当前预览和已导出状态。签名草稿按本机询价恢复，最终签名及完整内容随导出快照保存。签名可选，已有人工核对和导出条件保持一致。

## 询价审核保存状态（2026-11-08）
