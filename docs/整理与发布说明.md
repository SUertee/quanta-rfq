# 整理与发布说明

2026-11-07 从本地版本对比 worktree 建立独立仓库，使用当前工作区源码作为新的初始快照，不导入历史下载版本的 Git 提交。

## 纳入

当前 React/Vite 前端、Node 服务端、规则与 Agent、统一接收数据库迁移、附件和对话能力、设计文档、内置比赛样例与离线测试。提供无凭据的环境模板、统一测试入口、提交/推送密钥检查 hooks 和 GitHub Actions。

## 清理

- 移除失效的附件创建回调和相关类型、未使用的工具名称映射及页面导入。
- 移除已由整体变形小球替代的独立快捷输入 CSS。
- 去除前端对 `VITE_LLM_API_KEY`、`VITE_HUNYUAN_API_KEY` 的读取，防止环境凭据进入构建。
- 数据转换改为显式传入素材目录，构建评估数据使用相对工程路径，去掉旧电脑的盘符路径。
- 原始知识库、初版 Halden 参考页、旧独立演示、运行截图/导出、Windows 旧入口和手动远程模型探测脚本不进入独立仓库；原文件在本地旧目录保留，没有删除用户材料。

## 本地数据与发布边界

本地环境文件和库存数据库可以继续用于开发，但由 `.gitignore` 排除。新仓库不携带旧 Git 历史，不把密钥所在环境文件放入初始提交。样例 JSON 是应用所需的比赛素材副本，本机用户后来新增的文件与任务在 SQLite 中，不随推送发布。

归档和整理不会自动证明业务链路生产可用；真实模型、OCR、系统剪贴板和浏览器视觉仍应按实际环境验收。

依赖整理：Vite 更新到安全修复版本；测试直接声明 esbuild 开发依赖。ExcelJS 使用的 UUID 以局部 override 更新到兼容的 CommonJS 版本，保留 ExcelJS 业务接口并以真实表格解析回归验证。

## 本次验证

在独立目录使用 Node.js 22 安装依赖后，16组离线脚本全部通过，Vite 6.4.5生产构建通过，npm audit报告0个已知漏洞。暂存内容和构建产物均通过密钥规则扫描，另与旧目录本机环境中的真实密钥做精确比对，未发现匹配。浏览器视觉和真实OCR未因本次整理重新验收。
